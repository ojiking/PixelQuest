# PixelQuest: 블록 청소반 — 살아있는 기획서

> 웹 프로토타입으로 가설을 검증하면서 이 문서를 계속 갱신합니다.
> 실행: `python app.py` 후 `http://localhost:5000/game` (또는 `static/game/index.html`을 아무 정적 서버로 열기)

---

## 1. 한 줄 컨셉
**블록으로 변해버린 도시를 동료 로봇과 함께 청소하는 벨트스크롤 로그라이트.**
죽어도 모은 부품으로 동료 로봇을 개조해서 다시 출동한다.

## 2. 핵심 기둥 (Pillars)
| # | 기둥 | 검증 질문 |
|---|---|---|
| P1 | **때리는 맛** | 히트스톱, 넉백, 부위 파괴가 손맛을 주는가? |
| P2 | **동료 키우기** | 볼트가 강해지는 게 체감되고, 다음 런을 하고 싶게 만드는가? |
| P3 | **생김새 = 행동** | 처음 보는 적도 외형만 보고 행동을 예측할 수 있는가? |
| P4 | **공정한 난이도** | 죽었을 때 "내 실수"로 느껴지는가? (예고 동작, 보이는 함정) |
| P5 | **블록 바이옴** | 색과 블록 구성만으로 스테이지가 다르게 느껴지는가? |

## 3. 세계관 초안 (오리지널)
- **블록 쇼크**: 어느 날 도시의 물질이 1m 블록 단위로 굳어버린 재해.
- 플레이어는 민간 복구 업체 **'청소반'**의 신입. 무너진 구역을 점거한 폭력 조직 **'철거단'**을 몰아내며 구역을 정화한다.
- 동료 **볼트**는 청소반의 낡은 작업 로봇. 적에게서 회수한 **부품(⚙)**으로 개조한다. → 성장 시스템과 세계관이 자연스럽게 연결됨
- 적이 맞으면 블록 조각으로 흩어지는 것도 "블록화된 세계"의 규칙으로 설명 → 잔인함은 줄이고 쾌감은 유지

## 4. 현재 프로토타입 (v0.1) 내용
**게임 루프**: 타이틀 → 정비소(업그레이드) → 런(스테이지 2개) → 스테이지 사이 특성 선택 → 결과(부품 정산) → 정비소

| 시스템 | 구현 내용 |
|---|---|
| 조작 | 이동(8방향, 라인 이동), 3타 콤보, 점프, 날아차기, 줍기/던지기 |
| 타격감 | 히트스톱, 화면 흔들림, 넉백/다운/기상 무적, 백어택 x1.5 |
| 부위 파괴 | 머리/양팔/양다리 개별 체력. 파괴 시 복셀 파편으로 분해 |
| 부위 파괴 → 행동 변화 | 팔 없음 → 발차기만 / 투척병 팔 없음 → 근접형 전환 / 다리 하나 → 느려짐 / 다리 없음 → 기어감, 돌진 불가 / 머리 → 즉사 |
| 적 6종 | 골목 깡패(포위), 돌격 헬멧(예고 후 돌진), 벽돌 배달부(거리 유지+투척), 철거 덩치(슈퍼아머+내려찍기), 폭죽 꼬마(돌진 자폭, 죽어도 폭발), 보스 철거반장(2페이즈, 지원 호출) |
| 적 AI | 공격 토큰(플레이어에게 동시에 2명만 공격) + 대기 링, 위험 공격은 빨간 깜빡임 예고 |
| 동료 볼트 | 전술 3종(돌격/호위/협공), 다운 시 9초 후 자가 수리, 회전 차기, 구조 프로토콜 |
| 무기 3종 | 쇠파이프(넉백), 마체테(부위 파괴 특화), 콘크리트 블록(느리고 강함). 내구도, 던지기 |
| 오브젝트/함정 | 나무 상자(무기/음식/부품 드롭), 폭발 드럼통(연쇄), 가시 함정(적도 피해 → 유인 전략) |
| 바이옴 3종 | 폐허 초원 / 모래 공업지대 / 얼어붙은 항구 — 런마다 무작위 2개 |
| 로그라이트 | 런 내 특성 10종(3개 중 택1), 영구 업그레이드 7종(볼트 5종) |

## 5. 플레이 테스트 체크리스트
플레이 후 아래를 체크하고 느낀 점을 메모해 주세요. 다음 버전 우선순위를 정하는 근거가 됩니다.

- [ ] 첫 3타 콤보가 시원한가? 히트스톱이 너무 길거나 짧지 않은가?
- [ ] 부위 파괴가 자주/드물게 일어나는가? 일어났을 때 쾌감이 있는가?
- [ ] 팔이 떨어진 투척병이 근접형으로 바뀌는 것을 알아챘는가?
- [ ] 돌격 헬멧의 예고(빨간 깜빡임)를 보고 라인을 바꿔 피할 수 있었는가?
- [ ] 볼트가 도움이 됐는가, 방해가 됐는가? 전술 차이가 느껴지는가?
- [ ] 구조 프로토콜로 살아났을 때 볼트에게 애착이 생겼는가?
- [ ] 정비소에서 "다음엔 이걸 사야지" 하는 목표가 생겼는가?
- [ ] 가시 함정/드럼통으로 적을 처리하는 플레이를 시도했는가?
- [ ] 바이옴이 바뀌었을 때 다른 장소처럼 느껴졌는가?
- [ ] 한 런(약 5~8분) 길이가 적당한가?

## 6. 수치 조정 가이드
모든 기획 수치는 `static/game/js/config.js` 한 곳에 있습니다.

| 바꾸고 싶은 것 | 위치 |
|---|---|
| 공격 선딜/판정/후딜, 데미지, 넉백, 히트스톱 | `ATTACKS` |
| 적 체력/속도/크기/드롭 | `ENEMIES` |
| 스테이지별 적 등장 비율 | `SPAWN_POOLS` |
| 무기 성능/내구도/부위 파괴력 | `WEAPONS` |
| 볼트 기본 성능, 전술 | `BOT` |
| 바이옴 색 | `BIOMES` |
| 특성 / 업그레이드 비용 | `PERKS` / `UPGRADES` |

테스트 단축키: **B** 적 무작위 소환, **P** 픽셀 크기 변경

## 7. 다음 버전 후보 (백로그)
우선순위는 플레이 테스트 결과로 정합니다.

**v0.2 후보: 전투 깊이**
- 잡기 → 무릎차기 / 던지기 (적을 다른 적이나 함정으로 던짐)
- 회피(구르기) 또는 가드
- 적도 무기를 줍고 사용 (팔이 잘리면 무기를 떨어뜨림)
- 다운된 적 추가타(밟기)

**v0.2 후보: 동료 콘텐츠 강화**
- 볼트 파츠 슬롯 (팔/다리/머리/코어를 교체하는 장비 방식)
- 전술 칩 세분화: "체력 낮은 적 우선", "투척병 우선" 같은 조건-행동 규칙 편집
- 플레이어와 볼트의 합체 기술 (붙잡은 적에게 볼트가 돌진)
- 볼트가 무기를 주워 쓰거나 플레이어에게 건네줌

**v0.3 후보: 콘텐츠 확장**
- 적 종류 확장 (방패병, 사슬 휘두르는 적, 저격수, 땅굴 파는 적, 분열하는 적)
- 바이옴별 고유 함정 (용암 분출, 미끄러운 얼음, 컨베이어, 무너지는 블록)
- 스테이지 분기 선택 (어떤 바이옴으로 갈지 고르기)
- 사운드 (타격음은 타격감의 절반)

## 8. 열린 질문
- 볼트가 너무 강하면 플레이어가 구경꾼이 된다. 볼트의 역할은 "딜러"인가 "서포터"인가?
- 부위 파괴 확률을 무기 종류로 차별화할 것인가, 공격 방향(위/아래)으로도 나눌 것인가?
- 런 길이: 스테이지 2개(프로토타입) → 최종 몇 개? (예: 4바이옴 + 최종 보스)
- 메타 성장의 상한: 업그레이드를 다 사면 그 다음 동기는? (볼트 외형 커스터마이즈, 새 동료 등)
